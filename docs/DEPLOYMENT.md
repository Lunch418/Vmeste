# DEPLOYMENT.md — «Вместе»: как запустить у себя

## Готово ли приложение?

**MVP работает end-to-end** и покрыт тестами (102 backend + 11 frontend,
все зелёные на момент написания), но это **не готовый к продакшену продукт** —
несколько ключевых вещей осознанно заглушены (см. раздел «Что не по-настоящему»
ниже). Для демонстрации/личного использования на своей машине — можно
запускать прямо сейчас. Для реального запуска с деньгами пользователей —
сначала закрыть пункты из этого раздела.

Проверки безопасности проводились дважды: точечно на новой фиче
взаимного check-in (`specs/REVIEW.md`, `specs/CHANGES.md`) и отдельным
полным проходом по всему backend (см. итог в конце этого файла и в
`specs/SECURITY_REVIEW.md`). Все найденные Critical/Major на момент
написания — исправлены; актуальный список того, что осталось — там же.

## Что нужно на компьютере

| Инструмент | Версия (проверено) | Зачем |
|---|---|---|
| Python | 3.12 | backend |
| `pip` + `venv` | — | **часто отсутствуют в минимальной установке Linux** — см. «Проблема: нет pip» ниже |
| Node.js | 22.x (подойдёт 18+) | frontend |

Проверить, что уже есть:

```bash
python3 --version
python3 -m pip --version
node --version
npm --version
```

## Вариант А — Docker Compose (backend + Postgres + Redis)

Самый простой способ поднять backend с настоящей БД вместо SQLite:

```bash
docker compose up --build
```

Backend будет на `http://localhost:8000`, Postgres на `5432`, Redis на `6379`.
Frontend в Compose не описан — поднимается отдельно (см. «Frontend» ниже).

`JWT_SECRET` в `docker-compose.yml` — dev-значение по умолчанию.
**Обязательно смените**, если планируете открыть порт наружу (не localhost).

## Вариант Б — вручную (рекомендуется для разработки/отладки)

### Backend

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Без `.env` backend использует `sqlite:///./vmeste.db` — файл создастся
автоматически в `backend/`, миграции не нужны (см. «Известные ограничения»).

Проверить, что поднялось:

```bash
curl http://localhost:8000/health
# {"status":"ok"}
```

Тесты:

```bash
cd backend
.venv/bin/python -m pytest -q
# ожидается: 102 passed
```

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Откроется на `http://localhost:5173`, обращается к backend по
`VITE_API_BASE` (по умолчанию `http://localhost:8000`).

```bash
npm run build     # прод-сборка (tsc -b && vite build)
npm run test       # vitest, ожидается 11 passed
npm run lint       # oxlint
```

## Как проверить, что всё работает

1. Открыть `http://localhost:5173` в браузере.
2. Ввести любой телефон в формате `+79001234567` → «Получить код».
3. Код подтверждения **не приходит по SMS** (заглушка) — он пишется в лог
   backend-процесса. Найти его:
   ```bash
   # там же, где запущен uvicorn — ищите строку
   # "SMS to +79001234567: код подтверждения XXXX"
   ```
4. Ввести код → попадёте в ленту.
5. Создать событие («Создать» в нижнем меню) — на шаге «Дата, время,
   место» обязательно нажать **«Отметить точку встречи»** (запросит
   доступ к геолокации браузера) — без этого функция взаимного
   подтверждения явки не заработает для этого события.
6. После публикации — предложит внести депозит организатора (тоже
   заглушка ЮKassa, «оплата» проходит мгновенно).
7. Чтобы протестировать сценарий с двумя людьми — откройте приложение в
   двух разных браузерах/окнах инкогнито (браузер помнит токен в
   `localStorage`, поэтому одна и та же вкладка = один пользователь).

**Геолокация и камера требуют HTTPS** — кроме `localhost`, который браузеры
считают «secure context» по умолчанию. Если открываете фронтенд не с
`localhost`, а по IP из локальной сети (например, с телефона к ноутбуку) —
геолокация/камера работать не будут без HTTPS.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./vmeste.db` | Строка подключения к БД |

| `JWT_ALGORITHM` | `HS256` | |
| `JWT_EXPIRE_MINUTES` | `43200` (30 дней) | |

## Проблема: нет `pip`/`venv` (минимальная установка Linux)

На «голых» серверных Linux-образах Python часто ставится без `pip` и
`venv` отдельно. Симптом:

```
/usr/bin/python3: No module named pip
```

Решение (Debian/Ubuntu):

```bash
sudo apt install python3-pip python3.12-venv
```

Требует пароль sudo в реальном терминале — если работаете через
удалённую/автоматизированную сессию без интерактивного ввода пароля,
выполните эту команду в обычном терминале на своей машине один раз.
