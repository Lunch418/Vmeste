# SPEC.md — «Вместе»

Спецификация на основе `specs/TZ_Vmeste.md`, подтверждена продукт-оунером 2026-08-05.

## Решения по скоупу (подтверждено пользователем)

- **Депозиты**: полная интеграция ЮKassa Split (эскроу) сразу в MVP, без промежуточного ручного СБП-этапа.
- **AR-селфи с фильтрами**: ключевая фишка продукта, переносится в раннюю стадию разработки (не откладывается до v1.0).
- **Гео-запуск**: только Пермь, без гео-ограничений выше — жёстко фильтруем по городу на MVP.
- **Фронтенд**: пишет Claude Code по этой спецификации (отдельный агент/сессия реализации, не оркестратор).

---

## 1. Цель проекта

Дать пользователю находить компанию на конкретное офлайн-событие менее чем за 2 минуты, с гарантией явки через денежный депозит и безопасным подтверждением встречи (AR-селфи или QR). Первая цель — 10 реальных подтверждённых встреч в Перми на MVP, затем 500 активных пользователей и 200+ встреч/мес на v1.0.

Не входит в продукт: романтические знакомства, поиск работы/услуг, организованные мероприятия с организатором, анонимное общение, контент 18+, групповые чаты вне события.

---

## 2. Границы MVP (Этап 1)

**В MVP:**
1. Регистрация по телефону (SMS-код), профиль: фото, имя, возраст, город (только Пермь)
2. Лента событий (без карты) с фильтрами: тип активности, дата, размер депозита
3. Создание события — wizard 5 шагов (фото/афиша → тип активности → дата/время/место → места/возраст/пол → описание/депозит)
4. Присоединение к событию с депозитом через ЮKassa Split (эскроу)
5. Чат внутри события
6. Подтверждение встречи: **AR-селфи (MediaPipe Face Mesh, on-device)** с fallback на QR-код
7. Возврат/списание депозита по правилам (явка / no-show / отмена по срокам / форс-мажор через поддержку)
8. Оценка после встречи (1–5 звёзд), счётчик встреч и % явки в профиле
9. Базовые пуш-уведомления (новое событие в подписанной категории рядом; события чата)
10. Автоархивирование карточки события через 2 часа после времени встречи
11. Жалоба на пользователя, блокировка пользователя

**Не входит в MVP (переносится на v1.0 / v2.0):**
- Live-геолокация за 30 минут до встречи (WebSockets, мини-карта) — Этап 2
- Карта города (режим отображения событий) — Этап 2
- Верификация лица при регистрации (сравнение аватара и селфи) — Этап 2
- Кнопка SOS, автобан-логика по жалобам, снижение рейтинга за no-show — Этап 2
- Премиум-подписка, партнёрская реклама, интеграции Kassir.ru/KudaGo — Этап 3
- Нативные приложения iOS/Android — Этап 3
- Второй город, рекомендательный алгоритм — Этап 3

## 4. Экраны и компоненты

1. **Онбординг / Регистрация** — ввод телефона, SMS-код, заполнение профиля (фото, имя, возраст, город)
2. **Лента событий** (главный экран) — карточки событий, фильтры, счётчик «N встреч сегодня в городе»
3. **Карточка события** — фото/афиша, тип, дата/время, место, возраст, места, депозит, рейтинг постера, кнопка «Присоединиться»
4. **Создание события (wizard)** — 5 шагов, прогресс-бар как в сторис
5. **Чат события** — переписка участников до встречи, история сохраняется
6. **Экран депозита/оплаты** — виджет ЮKassa, статус эскроу
7. **AR-селфи подтверждение** — камера, случайный фильтр на двоих, кнопка «Отправить» активна при 2 лицах; альтернатива — генерация/сканирование QR
8. **Оценка после встречи** — звёзды + опциональный комментарий
9. **Профиль** — фото, имя, возраст, город, рейтинг, % явки, теги интересов, история встреч (своя), кнопка «Пожаловаться», «Заблокировать»
10. **Настройки** — уведомления, подписки на категории, город

Общие компоненты: карточка события, аватар с рейтингом, wizard-степпер, тост/пуш, модалка подтверждения оплаты.

## 5. API-эндпоинты (REST + WebSocket)

### Auth
- `POST /auth/phone` — запрос SMS-кода
- `POST /auth/verify` — подтверждение кода, выдача токена

### Users
- `GET /users/me`
- `PATCH /users/me`
- `GET /users/{id}` — публичный профиль
- `POST /users/{id}/report` — жалоба
- `POST /users/{id}/block`

### Events
- `GET /events` — лента с фильтрами (query: type, date, deposit_range, city)
- `POST /events` — создание
- `GET /events/{id}`
- `PATCH /events/{id}` — редактирование постером
- `DELETE /events/{id}` — отмена
- `POST /events/{id}/join` — присоединение (инициирует депозит)
- `POST /events/{id}/leave` — выход/отмена участия

### Deposits (ЮKassa Split)
- `POST /deposits` — создание платежа-эскроу
- `POST /deposits/{id}/webhook` — коллбек от ЮKassa
- `POST /deposits/{id}/refund` — возврат
- `GET /deposits/{id}`

### Chat
- `GET /events/{id}/messages`
- `POST /events/{id}/messages`
- `WS /ws/events/{id}/chat` — реалтайм сообщения

### Meeting confirmation
- `POST /events/{id}/confirm/selfie` — загрузка результата AR-селфи (метаданные, не сырое фото без согласия)
- `POST /events/{id}/confirm/qr/generate` — постер генерирует QR
- `POST /events/{id}/confirm/qr/scan` — джойнер сканирует
- `POST /events/{id}/rate` — оценка после встречи

### Notifications
- `POST /notifications/subscribe` — подписка на категорию/пуш-токен
- `GET /notifications`

## 6. Модели данных

**User**
`id, phone, name, age, city, avatar_url, rating_avg, meetings_count, attendance_rate, interests[], created_at, is_banned`

**Event**
`id, poster_id, photo_url, activity_type, datetime, location (lat, lng, address), age_range, gender_filter, slots_total, slots_taken, description, deposit_amount, status (active/archived/cancelled), created_at`

**Participation**
`id, event_id, user_id, status (joined/confirmed/no_show/cancelled), deposit_id, joined_at`

**Deposit**
`id, participation_id, payer_id, amount, escrow_status (held/released_to_payer/released_to_poster/refunded), yukassa_payment_id, created_at`

**Message**
`id, event_id, sender_id, text, created_at`

**Rating**
`id, event_id, rater_id, rated_id, stars, comment, created_at`

**Report**
`id, reporter_id, reported_id, event_id, reason, created_at`

## 7. Критерии приёмки

**Этап 0 (Фундамент)**
- Схема БД реализована и мигрирует чисто (Alembic)
- API-контракт (OpenAPI) сгенерирован из FastAPI и соответствует разделу 5
- Docker Compose поднимает backend + Postgres + Redis одной командой
- CI прогоняет линт и тесты на каждый PR

**Этап 1 (MVP)**
- Пользователь может зарегистрироваться по телефону и получить SMS-код
- Пользователь может создать событие за 5 шагов и увидеть его в ленте своего города
- Другой пользователь может присоединиться, оплатить депозит через ЮKassa (эскроу подтверждён вебхуком)
- Участники видят чат события и обмениваются сообщениями в реальном времени
- Встреча подтверждается AR-селфи с распознаванием двух лиц ИЛИ QR-кодом
- После подтверждения депозиты возвращаются обоим согласно правилам (раздел 3.3 ТЗ)
- No-show обрабатывается: депозит джойнера уходит постеру / штрафные правила постера применяются
- Пользователи могут оставить оценку друг другу после встречи
- Событие автоархивируется через 2 часа после времени встречи
- Демонстрация на реальных пользователях в Перми: минимум 10 подтверждённых встреч

Каждый этап проверяется оркестратором перед переходом к следующему.
